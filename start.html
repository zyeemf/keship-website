快速开始

两种方式：学生用预置镜像一键安装；开发者 clone 源码自行构建。

我是学生 — WSL 预置镜像 我是开发者 — git clone 源码

路径一 · 学生用户（推荐）

WSL 预置镜像：一键下载、一键安装

镜像已预装 ROS 2 Jazzy、Gazebo Harmonic、KeShip 与中文字体——导入即用，不配环境、不编译。

1

获取镜像文件

前往 WSL 预置镜像下载页 获取 KeShip 镜像（.tar，约 6.2 GB，版本以当期发放为准；页面显示尚未就绪时请在公众号「嵙舟求舰KeShip」留言）。镜像内已包含：Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic + KeShip 及全部依赖 + 中文字体。

2

导入 WSL（一条命令）

Windows PowerShell 
# 把镜像放到 D:\WSL\ 下，然后：
wsl --import KeShip E:\WSLDistros\KeShip D:\WSL\<镜像文件名>.tar --version 2

导入的是全新副本，不影响你现有的任何 WSL 发行版；目标目录 E:\WSLDistros\KeShip 可按需修改（预留 ≥ 30 GB 磁盘）。

3

一键启动

Bash 
# 推荐：双击 KeShip-Start.bat（与镜像在同一页面下载）
# 或在终端中：
wsl -d KeShip                            # 进入镜像内的 Ubuntu
~/keship_ws/start_keship.sh --no-build   # 启动（镜像已编译，跳过编译）

看到 KeShip 图形界面即成功。之后每次实验只需重复第 3 步。

i环境坏了怎么办

不要试图手工修复。删除重来即可：wsl --unregister KeShip，再按第 2 步重新导入——几分钟恢复全新环境。

i中文字体

镜像已内置中文字体；若自行修改过环境导致中文显示方框，装 fonts-noto-cjk 即可。

!只能开一个

同一时刻只运行一个 KeShip 实例；重复启动会被拒绝，这是保护机制，不是故障。

路径二 · 开发者

git clone 源码，自行构建

在独立 Ubuntu 或 WSL Ubuntu 中 clone 代码、配置环境、编译运行，适合二次开发与代码贡献。

1

克隆仓库

Bash · git 
# 国内推荐：Gitee（速度快）—— 克隆到 ~/keship_ws，与文档路径保持一致
git clone https://gitee.com/zyeemf/keship.git ~/keship_ws

# 国际：GitHub
git clone https://github.com/zyeemf/KeShip.git ~/keship_ws

# 网络受限时：SSH over 443
# git clone ssh://git@ssh.github.com:443/zyeemf/KeShip.git ~/keship_ws

# 团队协作：华为云 CodeHub
# git clone https://codehub.devcloud.cn-east-3.huaweicloud.com/fa858d905e994d968ddda3512bcd7c76/KeShip.git ~/keship_ws
Bash · 分支 
cd ~/keship_ws
git branch -a        # main（发布）/ dev（集成）/ feat/*（特性）
git checkout main    # 需要发布版时切换；日常开发用 dev
2

配置环境（Ubuntu 24.04 LTS）

Bash · 依赖安装 
# ① ROS 2 Jazzy
sudo apt update && sudo apt install -y software-properties-common
sudo add-apt-repository universe
sudo apt update && sudo apt install -y curl
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
sudo apt update
sudo apt install -y ros-jazzy-desktop python3-colcon-common-extensions

# ② Gazebo Harmonic
sudo apt install -y gz-harmonic

# ③ KeShip 依赖（ros-gz 桥接 / Assimp / Eigen3 / Qt5 / 中文字体）
sudo apt install -y \
  ros-jazzy-ros-gz-sim ros-jazzy-ros-gz-bridge \
  libassimp-dev libeigen3-dev \
  qtbase5-dev qtdeclarative5-dev \
  qml-module-qtquick2 qml-module-qtquick-controls2 \
  fonts-noto-cjk

完整从零指南见仓库内 doc/BUILD.md（随 git 分发、与代码同步更新）；依赖清单已与 CMakeLists.txt 的 find_package 逐项核对。

3

编译

Bash · colcon 
cd ~/keship_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select keship --merge-install
. install/setup.bash
4

启动

Bash · start_keship.sh 
# 一键启动：单例互斥 → 激活环境 → 编译闸门 → GPU 预热 → 启动
~/keship_ws/start_keship.sh
start_keship.sh 常用参数
参数作用
--no-build跳过编译，直接启动（代码未改动时更快）
--headless无 GUI 服务器模式（gz sim -s）
--no-d3d12WSLg 渲染异常时切换 llvmpipe 软件渲染
--no-gpu-warm跳过 GPU 预热
Bash · 手动启动（调试用） 
. install/setup.bash
ros2 launch keship keship.launch.py

✓跑通标志

终端无 BUILD FAILED → GPU 预热完成 → KeShip GUI 出现 → 在 GUI 中「载入模型」能看到船舶 → 实验完成。任一步卡住，先查下方注意事项。

!单例互斥

同一时刻只允许一个 KeShip 实例运行，重复启动会被明确拒绝。多实例会互相干扰（gz-transport 服务抢占、水域模型异常、波浪参数互篡改）。

i编译失败 ≠ 启动失败

编译失败时 install/ 里仍是上一次成功构建的旧版本——看到 BUILD FAILED 中止后，切勿误以为改动已生效。

i渲染后端

Windows WSLg + Mesa d3d12 组合若出现泄漏或偶发崩溃，用 --no-d3d12 切换 llvmpipe 软件渲染绕行。
